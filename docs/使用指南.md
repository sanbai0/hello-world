## 发文

继续在原有“学习总结”中写作，建议属性：

```yaml
---
title: 一篇笔记的标题
description: 一两句话概括本篇内容。
created: 2026-10-19
publish: true
tags:
  - Go
  - 排障
cssclasses:
  - pinned
---
```

置顶 `cssclasses: [pinned]` 可选，首页最多两篇。Syncer 保留 `cssclasses`，会过滤任意 `pinned`，不要为此打开全部 frontmatter。标签可以多选。

打开命令面板 `Quartz Syncer: Open publication center`，查看新增、修改和撤稿，选择这次要发布的笔记，点击 `PUBLISH SELECTED CHANGES`。插件直接更新 GitHub，Actions 自动构建并发布。没有保存即上传或定时发布。

用户已选择原版直接发布。日常流程就是“原库写好 → 发布中心点发布 → 网站自动更新”，不增加本地发布副本审核、附件许可清单或额外 Git 推送步骤。账号、仓库、插件安装及首次公开范围已确认。暂时的验收阻碍不作为日常操作步骤，见验收记录。

## 公开内容范围

- 公开文章里只引用愿意公开的图片和附件。原版会自动上传被引用的媒体，不要求给每张图片另设 publish，也无需在博客项目维护图片清单。
- 双链、嵌入会保留目标名称；被发布的关联文章可能被 Quartz 展开。写作时不要引用不愿公开的文件，原版没有额外的自动隐私拦截。
- 原始简历、同步凭据、令牌、`.obsidian` 和整个原库仍不属于公开范围。此要求不因取消额外审核而改变。
- `npm run audit:content` 与 `public-content.policy.json` 保留为可选的严格诊断工具，沿用前一方案的限制，可能把正常发文标为不符合旧规则；不参与预览、构建或 Actions，日常发文无需使用或维护它们。

## 更新、改名和撤稿

**更新**：修改原来的同一路径笔记，在发布中心选 Changed notes；插件更新同一仓库路径，不产生新文章。避免只为了改显示标题而改文件路径。

**改名/移动**：默认网址跟随文件路径。插件出现新路径新增、旧路径待撤稿，需同时检查两项，避免旧副本残留。旧网址默认失效；如需保留先设计别名/重定向。此次未改真实笔记。

**撤稿**：在原文把 publish 设为 false/去掉标记，再到发布中心选择对应 Published notes / Unpublish 并确认。仅去标记不代表网页已下线；只点 unpublish 却保留标记，下次可能重新发布。无需删除原文，避免影响原同步。核对撤稿路径，先处理其他文章对它的链接；孤立图片单独审核，不能删掉仍被引用的图。Actions 完成后实际检查旧网址和搜索索引。

撤稿不清除 Git 历史、浏览器或搜索引擎缓存。敏感信息不能先上传再删除；若已上传，必须另行处置历史和相关凭据。

## 部署排障

1. 仓库 → Actions → 最新 Deploy blog，查看失败步骤。Build 和 Deploy 均成功后，还要打开实际公开 URL。
2. 地址失败：核对账号/仓库与 `baseUrl`，分支为 `main`。
3. 文章没有出现：确认原笔记 publish 为 true、来源在学习总结、发布中心已选中，并核对插件目标仓库及分支为 main。普通发文不会运行旧的逐文件许可检查。
4. 安装/构建失败：本地先 `./scripts/blog.ps1 install` 再 `build`，保持两个锁文件一并提交，不盲目升级全部插件。
5. Pages 权限失败：Source 必须是 GitHub Actions，部署环境允许 main。工作流 build 只读 Contents，deploy 使用 Pages write 和 ID token write，不需要个人令牌写入 Actions。
6. 仍显示旧网页：比对提交 SHA、Actions 部署记录、实际网址及缓存，不能只看进程或构建成功。

免费 github.io 不保证中国大陆访问稳定。一次成功打开网页也不能代表大陆多网络访问稳定，本次不承诺速度和稳定性。
