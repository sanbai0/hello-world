## 先把问题说清楚

一篇技术笔记，不一定要从完整的理论讲起。可以先写下一个具体问题：**看到了什么现象，原本期待什么结果？**

把环境、输入和观察结果记下来，往往比直接写“解决了”更有价值。下一次遇到相似问题时，这些细节就是线索。

## 留下可以复现的过程

```typescript
type Note = { title: string; tags: string[]; publish: boolean }

const note: Note = {
  title: "一次小小的实践",
  tags: ["学习", "实践"],
  publish: true,
}

console.log(`记录：${note.title}；标签：${note.tags.join("、")}；这是一行用于检查手机端代码横向滚动的较长代码，不应撑开整页布局。`)
```

> [!tip] 写下为什么
> 除了最终做法，也保留选择它的理由，以及尚未解决的边界。

## 留给下一次的结论

1. 写出问题的具体表现。
2. 保留最小可复现过程。
3. 区分已经验证的结论和仍然不确定的判断。

技术记录的价值，在于能够再次被理解和使用。
