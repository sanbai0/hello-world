# 配置化规则设计：让限制有明确作用域，让执行结果可以追溯

把阈值从代码搬进配置文件，只完成了配置化的第一步。真正影响可维护性的，是某个值究竟对谁生效、多个值同时存在时选哪一个，以及一次拒绝决定能否被解释。

以文件处理平台为例：普通图片最多 20 MiB，设计源文件允许 200 MiB；免费租户与企业租户又有不同的限制。如果系统只有一个全局 `maxFileSize`，调整设计文件的上限，就可能同时放大普通图片的入口。问题不在阈值大小，而在阈值被放到了错误的层级。

## 让参数与决定它的规则待在一起

一种直观的配置结构，是把筛选条件和对应限制写成同一条规则：

```yaml
rules:
  - id: image-standard
    priority: 100
    match:
      tenantPlan: standard
      fileType: image
    limits:
      maxBytes: 20971520
  - id: design-enterprise
    priority: 200
    match:
      tenantPlan: enterprise
      fileType: design
    limits:
      maxBytes: 209715200
```

这里使用字节作为存储单位，避免 MB 与 MiB 在界面和服务端产生不同解释。配置界面可以显示易读单位，执行器只接收规范化后的整数。

| 参数 | 合理作用域 | 原因 |
|---|---|---|
| 单文件大小上限 | 规则 | 随文件类型和租户计划变化 |
| 单实例并发数 | 执行实例 | 由机器容量决定 |
| 服务请求超时 | 依赖调用 | 由调用契约和时间预算决定 |
| 租户日配额 | 租户 | 跨文件类型累计计算 |

相似的数值不一定属于同一层。把它们全部放在“高级设置”里，虽然表单更集中，却可能让运行时找不到明确的责任边界。

## 覆盖关系必须能用一句话说清

平台可能同时支持全局默认、租户覆盖和规则值。最怕的是不同代码路径采用不同顺序：上传入口用租户值，后台任务却重新读取全局值。

可以约定“规则显式值优先，其次租户值，最后全局默认”，并把解析收敛到一个函数。未填写表示继承，`0` 是否表示禁止必须单独规定，不能用 `if value` 把两种含义混在一起。

```text
resolveLimit(ruleValue, tenantValue, globalValue):
    if ruleValue is present:   return ruleValue, "rule"
    if tenantValue is present: return tenantValue, "tenant"
    return globalValue, "global"
```

解析结果同时返回数值和来源。这样排查“为什么这里限制 20 MiB”时，可以回答是命中了某条规则，而不只是展示最终得到的数字。

## 多条命中时，明确选择算法

优先级解决的是选择顺序，不自动解决冲突。如果两条相同优先级的规则都命中，依赖数据库偶然返回的第一条，会让规则调整变得不可预测。

对于“只执行一条规则”的模型，可以规定：按优先级选择最高者；最高优先级仍有多个匹配时，返回配置冲突。对适合叠加的限制，则可以明确采用交集或最严格值。两种模型都可行，关键是不能让执行器临时猜测。

规则发布前也可以检查明显的重复条件和无效范围。比如上限小于零、类型不存在、必填条件缺失，都应在配置进入运行环境之前报出。

## 决策日志记录经过，而不只是结论

一条“文件太大”的提示对用户够用，对维护人员却不够。内部决策记录可以保留以下结构：

```json
{
  "ruleId": "image-standard",
  "configVersion": "v12",
  "inputBytes": 25165824,
  "maxBytes": 20971520,
  "limitSource": "rule",
  "decision": "REJECT",
  "reason": "FILE_SIZE_EXCEEDED"
}
```

输入值、最终阈值和命中规则共同构成解释链。规则编号适合定位配置，配置版本适合定位当时的内容；如果只记录编号，而这条规则随后被修改，旧任务就很难还原。

对于运行时间较长的任务，还应在受理时保存已解析的规则快照或版本引用，让同一次任务前后使用一致参数。配置发布可以影响新任务，在途任务则继续遵守已经接受的约束。

验证配置化能力，最有代表性的用例不是改一个阈值看它生效，而是让两个作用域不同的任务并行执行，再检查继承、覆盖、冲突和决策记录是否符合约定。参数能改只是便利；参数为何生效、何时生效、对谁生效都可解释，配置才成为可靠的系统能力。
