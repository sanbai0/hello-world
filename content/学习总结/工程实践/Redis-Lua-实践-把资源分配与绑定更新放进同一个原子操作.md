# Redis Lua 实践：把资源分配与绑定更新放进同一个原子操作

一个在线支持平台有两位坐席：A 当前接待 3 个会话，B 接待 4 个会话。新访客进入时，系统选择负载更低的坐席，然后记录绑定关系，并把该坐席的负载加一。

单个请求看起来只有三步：读负载、选坐席、写绑定。但两个请求交错执行时，可能都读到 A 的旧负载；同一个访客的重复请求还可能建立两次绑定，导致负载重复增加。

这种问题适合把一次分配视为一个完整的状态变更，而不是几个彼此独立的 Redis 命令。

## 原子边界要覆盖“做决定”的过程

假设访客 U-42 的两个请求同时到达：

| 时刻 | 请求 1 | 请求 2 |
|---|---|---|
| t1 | 查到访客尚未绑定 | |
| t2 | | 查到访客尚未绑定 |
| t3 | 选择坐席 A | |
| t4 | 写入绑定，A 负载加一 | |
| t5 | | 再次写入绑定，A 负载加一 |

最后只有一个访客，却计入了两份负载。单独把 `HSET` 和 `ZINCRBY` 放进事务，仍然没有自动解决前面的并发判断；需要把“是否已有绑定”也放进同一个决策边界。

![已有绑定直接复用，新绑定在同一个 Lua 脚本内完成选择与负载更新](博客公开附件/工程实践/Redis-Lua-实践-把资源分配与绑定更新放进同一个原子操作.png)

Redis Lua 可以在脚本执行期间阻止其他命令插入这段读改写过程。后一个请求进入脚本时，会看到前一个请求已经写入的绑定，从而直接复用结果。

## 一个最小分配脚本

下面展示分配逻辑，不包含坐席上下线、会话结束等完整调度能力。约定绑定存于 Hash，负载存于有序集合，键类型已由初始化与校验保证。

```lua
-- KEYS[1]: {support}:bindings，visitorId -> agentId
-- KEYS[2]: {support}:loads，agentId -> activeCount
-- ARGV[1]: visitorId

local bound = redis.call('HGET', KEYS[1], ARGV[1])
if bound then
    return { 'EXISTING', bound }
end

local candidates = redis.call('ZRANGE', KEYS[2], 0, 0)
if #candidates == 0 then
    return { 'UNAVAILABLE', '' }
end

local agent = candidates[1]
redis.call('HSET', KEYS[1], ARGV[1], agent)
redis.call('ZINCRBY', KEYS[2], 1, agent)
return { 'ASSIGNED', agent }
```

这里最重要的是开头的“已有绑定优先”。相同访客重复进入时，不重新分配，不重新计数。若业务允许人工转接，应设计独立操作，明确解除旧关系、调整双方负载和写入新关系的顺序，而不是让普通分配请求暗中覆盖绑定。

返回值也区分了复用、新建和不可用。调用方不需要通过“结果是否为空”猜测脚本到底做了什么，日志和指标可以直接按结果类别统计。

## 原子执行不等于自动回滚

Redis 脚本的原子性主要指执行期间不被其他命令穿插。如果脚本写入第一项后，后续命令因类型错误失败，之前的写入不会自动恢复。

因此，参数和键类型检查应尽量在写操作之前完成，写入阶段保持短而确定。脚本不应包含不受限的遍历，更不适合承接长耗时计算，因为执行期间其他请求也需要等待。

示例中的 `{support}` 是 Redis Cluster 的哈希标签，使相关键落在同一槽中。实际分区可以按租户设置标签，在单个分配事务所需的键共槽与热点分散之间取得平衡。脚本访问的键通过 `KEYS` 显式传入，也便于检查它实际影响哪些数据。

## 分配与回收必须共享一套计数含义

建立绑定时加一只是半个生命周期。结束会话时，应先确认当前绑定仍属于待释放的坐席，再删除关系并减负载。重复结束通知不能减两次；发生过转接的旧通知也不能减少新坐席的计数。

若系统同时保存会话编号，那么幂等身份应明确是“访客当前会话”还是“访客长期身份”。同一访客结束旧会话后再次进入，可以合法建立新会话，不能被永久绑定挡住。

对于开头的 U-42，期望结果很具体：并发请求得到同一个坐席，绑定只有一份，负载只增加一次。Lua 的价值就在于把这三项约束放进一个短小的操作里，让调用方不必依靠多个网络往返维持它们的一致性。[Redis 脚本机制说明](https://redis.io/docs/latest/develop/programmability/eval-intro/)
