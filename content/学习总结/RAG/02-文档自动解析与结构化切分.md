# 文档自动解析与结构化切分

返回 [[学习索引]] · 后续 [[03-混合检索融合与重排序]]

## 条件、处理方式和例外放在一起，难道靠人工切分？

通常采用程序批量解析和切分，人工抽查、修正异常。“保留完整规则”是目标，不是每份文档必须人工编辑的要求，也不是自动解析能够保证的结果。

## 先解析结构，再组织片段

```text
原始文档
  → 解析标题、段落、列表、表格及位置
  → 根据章节和长度组织片段
  → 保存正文与元数据
  → 建立检索索引
```

Markdown、HTML 和规范 Word 可以利用已有结构。PDF 往往需要版面识别，扫描件还需要 OCR；文字顺序、表格合并单元格和跨页内容可能解析错误。

Unstructured 提供先识别文档元素、再按元素或标题切分的机制。这能帮助保留结构，但不等于自动理解所有业务例外。[官方文档](https://docs.unstructured.io/open-source/core-functionality/chunking)

## 为什么按标点停止仍不够

```text
第一段：以下规则仅适用于 A 渠道。
第二段：超过 10 分钟应转人工。
第三段：指定活动期间延长到 20 分钟。
```

每句都完整，但只拿第二段会丢失适用范围和例外。固定字数与重叠只是辅助策略，不能保证规则完整。

可以设计：标题确定章节，相邻段落在长度允许时合并；长章节再细分，但保存父章节引用。

```json
{
  "chunk_id": "C102",
  "parent_id": "SECTION_A",
  "heading": "A 渠道出票规则",
  "text": "超过 10 分钟应转人工。",
  "source_page": 12
}
```

命中 C102 后，通过父章节引用补充完整规则或关联段落。补充材料同样要检查权限和上下文预算，不能无限扩大。

## 表格怎么处理

保留表标题、列名、单位和注释的关联。长表需要按行分块时，可由程序为每块重复附加表头，并关联适用的单位和脚注。

前提是这些结构已被正确识别。单位或说明不确定时不能自行编造，应标记异常或复核。

## 大批文档的质量控制

- 自动发现空正文、异常短片段、疑似缺表头等情况。
- 保存来源、页码、版本、渠道、权限等元数据及原始内容引用。
- 抽查不同文档类型，使用含例外条款的问题验证检索。
- 必要时用模型辅助识别规则关系，但保留原文依据并核验。
- 对重要且解析失败的文档人工修正，或暂不用于回答。
- 对新增或变化的文档增量处理，更新索引并处理旧版本适用范围。

人工主要处理异常与质量验收。格式识别、切分、索引建立由程序批量执行。
