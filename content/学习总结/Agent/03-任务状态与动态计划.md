# Agent 学习 03｜任务状态与动态计划

返回 [[学习索引]] · 相关 [[04-结束条件与业务验收]]

## 状态是什么

状态是程序在一次任务执行过程中保存的信息。除了聊天记录，还可以有明确的字段：

```python
state = {
    "task_id": "T001",
    "goal": "调查某店铺昨天出票成功率是否下降及相关线索",
    "scope": {"shop_id": "S001", "date": None},
    "status": "running",
    "messages": [],
    "plan_version": 0,
    "plan": [],
    "evidence": {},
    "tool_call_count": 0,
    "max_tool_calls": 8,
}
```

这里的最大调用次数是示例配置。“昨天”需要按约定时区解析成具体日期；不清楚店铺或指标口径时，应先澄清。

消息历史适合保留交流过程；结构化状态让程序更容易回答“已经查过什么、还缺什么、调用了几次、当前为什么停下”。

## 状态和模型上下文有什么关系

完整状态保存在程序侧。每次请求模型时，程序选择相关状态、消息和工具结果放入上下文，模型才能利用它们。

**保存了状态，不代表模型会自动读到它。** 没有必要每次把所有历史和原始数据全部塞给模型。

模型可以提出计划或字段更新建议，程序验证后保存。权限、调用计数和完成状态等关键字段不能由模型任意覆盖。

## 怎样让模型提出可检查的计划

可以给模型这样的要求：

```text
目标：调查昨天指定店铺出票成功率下降的原因。

可用工具：
- compare_success_rate：比较两个日期的成功率
- list_failed_orders：查询指定日期的失败订单
- get_ticket_receipts：查询指定订单的出票回执

请提出最多 3 步的行动计划。
每步包含 id、goal、tool、depends_on。
只使用提供的工具。
先核实下降是否存在，再调查原因。
```

一种候选计划：

```json
[
  {"id":"P1","goal":"核实成功率是否下降","tool":"compare_success_rate","depends_on":[]},
  {"id":"P2","goal":"若下降则查询失败订单","tool":"list_failed_orders","depends_on":["P1"]},
  {"id":"P3","goal":"检查失败订单的回执线索","tool":"get_ticket_receipts","depends_on":["P2"]}
]
```

计划用来表达准备做什么，不等于工具已经调用。实际执行时仍要补齐日期、店铺或订单 ID，并经过参数和权限检查。

程序可检查工具是否存在、步骤 ID 是否唯一、依赖是否有效、有无循环，以及步骤数量是否超限。自由文本目标是否有意义，还需要结合任务判断。

## 怎样保存计划与进度

```python
# 示意代码：先验证，再保存允许的字段。
validated = validate_plan(model_plan)
state["plan_version"] = 1
state["plan"] = [
    {
        "id": step["id"],
        "goal": step["goal"],
        "tool": step["tool"],
        "depends_on": step["depends_on"],
        "status": "pending",
        "result_ref": None,
    }
    for step in validated
]
```

当 P1 的工具执行并满足该步骤的完成要求后，由程序记录其状态和结果引用，例如 `status="completed"`、`result_ref="E001"`。

模型说“我已经完成了查询”不能替代实际工具结果；工具虽然执行结束，结果不完整时也不能直接视为已完成该业务步骤。

## 怎样随结果调整计划

假设 P1 返回：昨天和前天的成功率都是 80%，且两天口径一致、数据完整。

原先“成功率下降”的前提没有得到支持。模型可以建议取消 P2、P3，先报告未发现下降，或向用户核对日期和口径。

程序验证后保存新版本，记录调整理由和引用的 E001，保留旧计划供排查。不要为了完成原计划而继续寻找不存在的下降原因。

如果数据确实下降，则继续 P2，并根据结果中的订单 ID 组织 P3 的参数；如果 P1 数据不完整，则补查或说明限制。

## 状态存在哪里

学习阶段可以先放在 Python 字典里；需要跨进程保留时，再保存到文件或数据库。

状态持久化并不自动保证任务可以安全恢复。恢复后仍要处理身份权限、数据时效，以及退款、转人工等动作是否已经执行，避免重复操作。
